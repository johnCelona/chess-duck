# Backend rules

Python 3.12 package `duckgambit`, managed with uv (`backend/pyproject.toml`, `backend/uv.lock`). Run everything from the repo root with `uv run --project backend ...`.

## Layers (enforced by `tests/unit/test_architecture.py`)

| Folder | May import | Holds |
| --- | --- | --- |
| `domain/` | stdlib (no I/O), `chess`, `chess.pgn` | ducks, knowledge, decision layer, clock, balance, ratings, PGN, events, lessons, review, puzzles, tournaments |
| `services/` | `domain`, `services` | use cases and ports (Protocols): matches, jobs, events, ducks, engines, Lichess |
| `adapters/` | `domain`, `services`, `settings` | UCI engine and pool, installer, SQLite store, fakes |
| `api/`, `cli/` | everything | composition root (`api/container.py`), routers, wire schemas |

The domain never reads a clock, an environment variable, a file, or global randomness. Time, ids and seeds are arguments.

## Determinism (anything that affects a result)

- Seeds: `domain/seeds.py` (`derive_seed`, `rng_for`, `draw_below`, `pick_weighted`). Integer arithmetic only where the outcome depends on it.
- Engine searches are stateless: `ucinewgame` before each, Threads 1, node or depth limits. Never `go movetime`, never `Skill Level` or `UCI_Elo` in rated play.
- A change that could alter a move for the same inputs bumps `DECISION_LAYER_VERSION` (`domain/decision.py`). A change to any balance number bumps `Balance.version` (`domain/balance.py`). Both are part of the rating context.

## Data

- SQLite through `adapters/sqlite/`. Schema changes are new numbered files in `adapters/sqlite/migrations/`, forward-only; never edit a shipped migration. Nested values live in versioned JSON `doc` columns with upcasters.
- Live games against a human (ADR-0015): `services/sparring.py`. They are not jobs: the human's time is measured there and passed in as data. The duck replies in a task through `services/duck_turn.py`, shared with the match runner. Best-of series rules: `domain/series.py`. House challengers: `domain/challengers.py`, profile `prof_house`. They never gain XP.
- One local profile (`prof_local`) owns every duck and remembers the active duck (`GET /profile`, `PUT /profile/active-duck`). A duck's `egg_seed` sets its starting stats only (`domain/duck.stats_from_egg`).
- All mutable files go under the data directory (`adapters/system.DataPaths`), never the source tree. Paths built from input go through `safe_child`.

- Minigame tests (ADR-0017): `domain/minigames/` (one file per game, listed in `catalog.py`), runs in memory only. `content.py` is generated by `scripts/build_minigame_content.py`; never edit it.

## API

- Wire schemas live in `api/schemas/` (camelCase on the wire, `WireIn` rejects unknown fields). After any change: `npm run gen` and commit `contracts/` plus the generated TypeScript.
- Errors are RFC 9457 problems with stable `code`s (`api/errors.py`). Never send exception text or paths to a client.
- A new domain event needs a dataclass in `domain/events.py` and a wire schema in `api/schemas/events.py`; `tests/api/test_contracts.py` checks they match.

## Tests

- Fakes: `adapters/engines/fake.py` (in-process) and `tests/fakes/fake_uci.py` (a UCI process with hang, crash, reorder modes). CI never has Stockfish; `tests/real/` skips without it.
- Golden files in `tests/golden/` cover the walking-skeleton PGN and event stream. Update with `--update-golden` only for an intended change, and say why in the commit.
